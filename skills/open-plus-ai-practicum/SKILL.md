# Open Plus · AI-практикум (HTML-колода)

## Когда применять

Используй этот skill, если пользователь просит:

- практикум / воркшоп по работе с GenAI-ассистентом;
- колоду «сначала руками на общем кейсе → потом свой навык»;
- слайды с готовыми промптами, шагами практики и заметками ведущего;
- визуальный стиль референса `AI Практикум_Д.Драпеза.html`.

Не используй для keynote «Фабрика будущего» (кейсы заводов, 3D, тренды) — там отдельный skill `open-plus-factory-future`.

## Эталон

| Что | Значение |
|---|---|
| Файл | `AI Практикум_Д.Драпеза.html` в корне репозитория |
| Язык | русский |
| Объём эталона | ~145 слайдов |
| Формат | один self-contained HTML: CSS + JS + watermark внутри файла |
| Шрифт | Montserrat (fallback Arial) |
| Навигация | ←/→, клик prev/next, overview (`O`), заметки ведущего, таймер |

**Рабочий метод:** не собирай CSS/JS с нуля. Скопируй эталон → оставь `<style>`, chrome (`nav`, `overview`, `notes-panel`, `timer-overlay`) и рабочие `<script>` → замени только `<section class="slide …">` внутри `<main class="deck">` и обнови `<title>` / data-константы в первом скрипте.

### Визуальные правила

- Светлый слайд: белый фон, водяной знак справа снизу (уже в CSS `:before`).
- Тёмный слайд (`.dark`): глубокий navy-градиент, акценты `#63aaff` / cyan / violet.
- Акцент в заголовке: `<span class="accent">…</span>`, иногда `<span class="cyan">…</span>`.
- Заголовок короткими строками с `<br>`; одна мысль на слайд.
- Не добавляй «карточки ради карточек» в hero; сетки (`grid2/3/4`) — только для сравнения или выбора.
- Избегай фиолетово-белого «AI-клише» и кремовых серif-тем: палитра уже задана Open Plus (синий + cyan + violet как поддержка).

### Каркас слайда

```html
<section class="slide v2" data-title="Короткое имя для overview">
  <div class="top">
    <span class="chapter">Рубрика в шапке</span>
    <span class="counter"></span>
  </div>
  <div class="content">
    <h2>Заголовок<br><span class="accent">акцент</span></h2>
    <!-- тело -->
  </div>
  <div class="bottom"><span class="small"></span></div>
  <aside class="notes">
    <b>Что сказать.</b> …<br>
    <b>Акцент.</b> …<br>
    <b>Переход.</b> …
  </aside>
</section>
```

`data-title` обязателен (картотека overview). `counter` заполняется скриптом. Заметки в `.notes` — для ведущего, на экране скрыты.

## Архитектура дня (логика колоды)

Сохраняй эту драматургию, даже если меняются кейсы и длительность:

1. **Вводная** — цель дня, сообщество/канал, проверка инструмента, маршрут, артефакты на выходе, роли в командах.
2. **Ваши задачи** — вопрос залу → «интеллектуальная рутина» → спрос аудитории → критерии отбора → кейсы дня → уровни компетенций.
3. **Как работает ассистент** — модель / контуры данных / лестница «чат → ассистент → агент» → практика формулировки задачи → промпт и контекст → практика промпта → возможности инструмента.
4. **Часть 1 · общий кейс** — один сквозной файл/датасет; шаги одного паттерна:
   - задача → что получится → делаем вместе (промпт) → где ещё пригодится;
   - между шагами — короткая теория (токены, контекст, калькулятор, HTML-артефакт, критика ролями).
5. **Мост** — пауза / внешний блок / возврат с одним спорным выводом.
6. **Часть 2 · свой навык** — чат/ассистент/агент → ошибки агента → готовый Skill → описание своего процесса → сборка Skill → треки команд → проверка / «сломайте навык» → питч 90 сек → финал.

Новая колода может быть короче эталона, но не должна терять петлю **теория → практика → перенос**.

## Каталог типов слайдов

### 1. Обложка / раздел (тёмный divider)

Классы: `slide v2 dark chapter-slide v2-div`  
Опционально: `data-net="R,G,B"` (нейросеть-фон).

```html
<section class="slide v2 dark chapter-slide v2-div" data-net="95,166,255" data-title="…">
  <div class="top"><span class="chapter">…</span><span class="counter"></span></div>
  <div class="content">
    <div class="chapter-no">01</div>
    <span class="eyebrow">…</span>
    <h1>Заголовок<br>с <span class="accent">акцентом</span></h1>
    <div class="hero-kicker">Одна поддерживающая фраза.</div>
  </div>
  <div class="bottom"><span class="small"></span></div>
  <aside class="notes">…</aside>
</section>
```

### 2. Практическое задание (разделитель практики)

Классы: `slide v2 chapter-slide v2-div v2-prac` (для части 2 часто `v2-prac-blue`).

```html
<section class="slide v2 chapter-slide v2-div v2-prac" data-net="2,109,244" data-title="Практическое задание · …">
  <div class="top"><span class="chapter">Практика</span><span class="counter"></span></div>
  <div class="content">
    <span class="eyebrow">Практическое задание</span>
    <h1>Глагол + конкретный результат</h1>
    <ol class="v2-prac-steps">
      <li>Шаг</li><li>Шаг</li><li>Шаг</li>
    </ol>
  </div>
  …
</section>
```

### 3. Промпт «делаем вместе»

Классы тела: `prompt-shell` + `prompt` + боковая колонка `why` с `.card`.

```html
<h2>Делаем вместе<br><span class="accent">…</span></h2>
<div class="prompt-shell">
  <div class="prompt">
    <pre data-prompt data-prompt-id="pXX">Текст промпта.
Поля для участника: <span class="fill">[что подставить]</span></pre>
    <button class="copy-btn">Копировать</button>
  </div>
  <div class="why">
    <div class="card"><b>Что сделать</b><ol class="v2-clicks"><li>…</li></ol></div>
    <div class="card warn"><b>Если не работает</b><strong>…</strong><span>…</span></div>
  </div>
</div>
```

Правила промпта на слайде:

- копируемый текст готов к вставке в ассистент;
- плейсхолдеры только в `<span class="fill">[…]</span>`;
- справа — 3–5 кликов «что сделать», не теория;
- в notes указать канал/пост, если есть фасилитатор чата.

### 4. Шаг кейса: задача / результат / перенос

- **Задача:** `grid3` — вход / действие / выход.
- **Что получится:** один конкретный артефакт (таблица тем, дашборд, цитаты), без абстракций.
- **Где ещё пригодится:** `grid2` — «эта ситуация» / «другие ситуации».

### 5. Карточки сравнения / выбора

`grid2`, `grid3`, `grid4` + `.card`; для кейсов дня — `v2-cases` и критерии `.v2-crit`.

### 6. Маршрут дня

`div.route.v2-route` с двумя `.route-part` и мостом `.route-bridge`.

### 7. Теория с визуалом

Переиспользуй готовые layout-классы эталона, не изобретай новые без нужды:

| Тема | Классы / паттерн |
|---|---|
| Лестница модель→агент | `lad-stack` |
| Петля обучения | `v2-loop` |
| Анатомия промпта | `prompt-anatomy`, `prompt-parts` |
| Контекстное окно | `cw-layout`, `cw-stack` + data-атрибуты демо |
| Петля агента | `agent-loop-board` |
| Харнес | `harness-layout` |
| UI Skills | `ca-skill-ui` |

Если нужного визуала нет — простой `grid` + короткий текст лучше, чем новый CSS.

## Входные данные от пользователя

Собери (спроси коротко, если не дано):

1. **Аудитория** — роли, уровень, размер групп.
2. **Инструмент** — название ассистента/модели, канал материалов (Teams и т.п.).
3. **Артефакты дня** — 2–4 конкретных выхода у участника.
4. **Общий кейс части 1** — файл/таблица, шаги разбора, эталон «как правильно».
5. **Критерии отбора задач** — 4–6 «да» и 4–6 стоп-сигналов.
6. **Треки части 2** — 2–4 домена со входом, риском и ответственным человеком.
7. **Тайминги** — только в notes/фасилитации; на слайдах время не обещать жёстко.
8. **Тон** — «практикум, не лекция»; обращение на «вы».

## Редакционные правила

- Одна идея = один слайд. Заголовок — утверждение или глагол действия, не тема «О промптах».
- Сначала работа / боль аудитории, потом инструмент.
- Не пиши «ИИ всё сделает»; подчеркивай проверку человеком, эталон, ответственного.
- Промпты — рабочие, не декоративные. Если шаг не делается руками — это не практика.
- В `.notes` всегда: что сказать, акцент, переход; для практики — время и канал.
- Нумерация шагов сквозная внутри части; `data-title` уникален и узнаваем в overview.
- Первый слайд дня: `class="slide v2 dark active"`.

## Процесс генерации

1. Прочитай эталон и этот skill.
2. Зафиксируй бриф (YAML выше).
3. Скопируй эталонный HTML в новый файл (`Название практикума.html`).
4. Обнови `<title>`.
5. Удали/замени секции слайдов; сохрани chrome и скрипты.
6. В первом `<script>` обнови объект `CASES` и любые демо-константы под новые кейсы; удали мёртвые demo-блоки, если слайдов с ними больше нет (но не ломай общий nav/overview/net/fit-text).
7. Для тёмных слайдов чередуй `data-net` (синий / cyan / violet оттенки RGB).
8. Пройди QA-чеклист.
9. Открой файл в браузере: стрелки, overview, копирование промпта, notes.

## QA-чеклист

- [ ] Ровно один `.slide.active` на старте.
- [ ] У каждого слайда есть `data-title`, `.top`/`.content`/`.bottom`, осмысленные `.notes`.
- [ ] Overview показывает все слайды; поиск по заголовку работает.
- [ ] Промпты копируются кнопкой; плейсхолдеры визуально отличимы.
- [ ] Часть 1 сходится к артефактам; часть 2 — к защищаемому Skill.
- [ ] Нет «простыней»: заголовки читаются с проектора (короткие строки).
- [ ] Стили и watermark на месте; шрифт Montserrat.
- [ ] Нет битых `data-case` / `data-prompt-id` после замены контента.

## Чего не делать

- Не переписывай весь CSS (~1500 правил) и watermark.
- Не вставляй Reveal/PowerPoint/Marp — формат эталона обязателен.
- Не превращай практикум в лекцию без «делаем вместе».
- Не добавляй статистику и вторичный маркетинг на обложку: бренд/название дня, один заголовок, один kicker, один CTA/переход.
