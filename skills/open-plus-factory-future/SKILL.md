# Open Plus · Фабрика будущего (HTML-колода)

## Когда применять

Используй этот skill, если пользователь просит:

- keynote / доклад «фабрика будущего», industrial AI, цифровой завод;
- колоду из производственных кейсов с паттерном «ограничение → кейсы → вывод»;
- слайды под живой рассказ с заметками спикера и внешним взглядом на карту заказчика;
- визуальный стиль референса `Фабрика будущего — Open Plus день 1.html`.

Не используй для hands-on практикума с промптами и Skills — там skill `open-plus-ai-practicum`.

## Эталон

| Что | Значение |
|---|---|
| Файл | `Фабрика будущего — Open Plus день 1.html` |
| Язык | русский |
| Объём эталона | ~76 слайдов |
| Формат | один self-contained HTML (CSS + JS; опционально Three.js-сцены) |
| Шрифт | Montserrat |
| Навигация | ←/→, overview, notes-panel |

**Рабочий метод:** скопируй эталон → сохрани `<style>`, chrome и скрипты → замени слайды в `<main class="deck" id="deck">`. 3D-сцены (`THREE`, `s3d-*`) переноси только если новый кейс реально нуждается в том же визуале; иначе оставь 2D layout `case-company` / `cc-steps` без canvas.

### Визуальные правила

- Светлые слайды: белый фон + watermark справа снизу.
- `.dark` — обложки и смысловые точки сборки (глубокий navy + cyan).
- `.human-divider` — разделы «сначала о человеке» / «что это значит» (бирюзово-тёмный градиент).
- Акцент в заголовке: `<span class="accent">…</span>`.
- Подписи источников — `.source` внизу; тип кейса — `.tag`.
- Одна сильная формулировка на слайд; цифры только с оговоркой происхождения (поставщик / исследование / оценка).

## Драматургия доклада

Сохраняй дугу, даже при замене кейсов:

1. **Человек и предел** — рабочая память, цена переключений, лавина сигналов на производстве.
2. **Контекст изменений** — технологические волны, скачок способностей, как проверяют перенос правил (бенчмарки).
3. **Тренды** — 2–4 тренда с «как выглядит на практике», не список вендоров.
4. **Визионерский тезис** — одна фраза (у эталона: конкурируют циклы обучения).
5. **Карта заказчика** — «не с чистого листа»; доклад продолжает их направление.
6. **Принципы работы с изменениями** — цикл ограничений; «не автоматизировать хаос»; агент не выводит регламент сам; фабрика шире ИИ; роли промышленного ИИ.
7. **Семейства кейсов** — 3–5 блоков одного шаблона:
   - слайд-ограничение (`.chapter-slide` + роли ИИ);
   - 2–4 кейса;
   - вывод-паттерн (`.concl` + `flow3`).
8. **Обратная сторона** — сбои платформ, кибер, избыточная автоматизация, риск автономных агентов, предохранители.
9. **Место человека и синтез** — роль в контуре, уровни доказательства цифр, сравнение траекторий, возврат к карте заказчика.
10. **Финал** — 5 вопросов к инициативе / новый способ работы, не «сумма технологий».

Типичные семейства эталона (можно переименовать под отрасль):

| # | Ограничение | Паттерн вывода |
|---|---|---|
| 1 | Поток видит отклонение слишком поздно | Сигнал → решение → действие |
| 2 | Контроль сам стал узким местом | Разная глубина контроля |
| 3 | Данные заказа/запаса/линии разорваны | Платформа снижает стоимость следующего изменения |
| 4 | Изменение линии/режима слишком дорого | Сначала цифра, потом металл / помощник инженера |

### 2. Human / смысловой divider

`class="slide dark human-divider"` — короткий заголовок без сетки.

### 3. Chapter семейства (ограничение)

```html
<section class="slide chapter-slide" data-title="…">
  <!-- опционально: .cyc-mark с шагом цикла -->
  <div class="top"><span class="chapter">Семейство N</span><span class="counter"></span></div>
  <div class="content">
    <div class="chapter-no">0N</div>
    <h2>Ограничение <span class="accent">в операторских словах</span></h2>

    </div>
  </div>
  <div class="bottom">
    <span class="small">…</span><span class="tag">ограничение</span>
  </div>
  <aside class="notes">…</aside>
</section>
```

### 4. Кейс завода (основной шаблон)

```html
<section class="slide" data-title="Компания · коротко" data-own-notes>
  <div class="top"><span class="chapter">Тема · площадка</span><span class="counter"></span></div>
  <div class="content cc">
    <!-- при иллюстрации: добавь has-ill и .cc-media -->
    <div class="cc-copy">
      <span class="case-company">Компания · площадка</span>
      <h2>Что изменилось <span class="accent">в работе</span></h2>
      <div class="cc-steps">
        <div class="cc-step now">
          <i>01</i>
          <div>
            <strong>Проблема / исходное состояние</strong>
            <span>Цена или симптом</span>
          </div>
        </div>
        <div class="cc-step now">
          <i>02</i>
          <div>
            <strong>Что сделали</strong>
            <span>Механика, не бренд</span>
          </div>
        </div>
        <div class="cc-step now">
          <i>03</i>
          <div>
            <strong>Новый способ работы</strong>
            <span>Кто решает / что блокируется автоматически</span>
          </div>
        </div>
      </div>
      <div class="cc-nums">
        <div><strong>…</strong><span>единица эффекта</span></div>
        <div><strong>…</strong><span>вторая метрика или оговорка</span></div>
      </div>
      <div class="cc-note">Источник цифр / что не раскрыто.</div>
    </div>
  </div>
  <div class="bottom">
    <span class="source">…</span>
    <span class="tag">CV + контур / платформа / …</span>
  </div>
  <aside class="notes">Один акцент для зала + ограничение кейса.</aside>
</section>
```

Правила кейса:

- заголовок = изменение работы, не название продукта;
- 3 шага: было → механизм → новое состояние контура;
- цифры всегда с `.cc-note` (поставщик / оценка / не раскрыто);
- тег снизу — технология + роль в процессе, не логотип-суп.

### 5. Вывод блока (паттерн)

```html
<section class="slide" data-title="Паттерн: …">
  <div class="top"><span class="chapter">Вывод блока N</span><span class="counter"></span></div>
  <div class="content concl has-ill" style="--acc:#10cbb4;--tint:#e9fbf8">
    <aside class="concl-side">
      <div class="concl-num">0N</div>
      <div class="concl-was"><b>Было</b>…</div>
      <div class="concl-arrow">↓</div>
      <div class="concl-now"><b>Ответ</b>…</div>
    </aside>
    <div class="concl-main">
      <h2>Переносимая формулировка <span class="accent">паттерна</span></h2>
      <div class="flow3">
        <div class="fn"><b>A</b><strong>…</strong></div>
        <div class="arr"><i></i>→</div>
        <div class="fn"><b>B</b><strong>…</strong></div>
        <div class="arr"><i></i>→</div>
        <div class="fn"><b>C</b><strong>…</strong></div>
      </div>
    </div>
  </div>
  <div class="bottom">
    <span class="small">…</span>
    <span class="tag">переносимый паттерн</span>
  </div>
  <aside class="notes">Вернуть к карте заказчика, не продавать проект.</aside>
</section>
```

### 6. Вопрос в зал

Короткий h2-вопрос + простая сетка вариантов (`.trace-grid` и аналоги) или совсем без сетки. В notes — как собрать ответы и к чему перейти.

### 7. Риск / агентность

Тёмные или плотные схемы (`.risk-dark`, `.ag-grid`, `.ag-chain`, таймлайн). Тон: архитектура предохранителей, не страшилка. Всегда заканчивай конструктивным слайдом границ автономности.

### 8. Финал

`.dark` + 5 вопросов к инициативе или один сильный вопрос «какой способ работы меняем первым». Можно опереться на `.mechanic-viz` только если визуал уже в скриптах эталона и кейс совпадает.

## Входные данные от пользователя

1. **Заказчик / аудитория** — отрасль, зрелость, «карта» текущих направлений.
2. **Тезис дня** — одна фраза вместо «каталога технологий».
3. **Семейства ограничений** — 3–5 проблем в языке операций.
4. **Кейсы** на семейство: компания, площадка, было/сделали/стало, 1–2 метрики, источник, тег механики.
5. **Роли промышленного ИИ** — словарь (измерять / оптимизировать / действовать / …).
6. **Риски**, которые нельзя обойти молчанием в этой аудитории.
7. **Вопросы финала**, привязанные к их инициативам.
8. Нужны ли **3D-иллюстрации** (по умолчанию — нет, если нет готовой сцены).

## Редакционные правила

- Не соревноваться количеством AI-use-cases. Каждый кейс должен показывать **изменение способа работы**.
- Сначала ограничение человека/потока, потом технология.
- «Фабрика будущего шире ИИ» — оставляй линзу альтернатив (не везде нужен ИИ).
- Не автоматизировать хаос: без правил агент не спасёт.
- Цифры честно маркируй; лучше меньше метрик, чем неподтверждённый эффект.
- Говори «контур», «задержка», «глубина контроля», «стоимость следующего изменения» — это язык паттернов эталона.
- Notes пишутся для устного рассказа: один акцент, одно ограничение кейса, переход.
- На обложке только бренд/название, тезис, kicker — без статистики и расписания.

## Процесс генерации

1. Прочитай эталон и этот skill.
2. Собери бриф YAML.
3. Скопируй эталонный HTML в новый файл.
4. Обнови `<title>` и обложку.
5. Пересобери слайды семейств по шаблонам; выкини кейсы, которых нет во входе.
6. Если удаляешь 3D-кейсы — можно оставить скрипт Three.js (он тяжёлый, но безвреден) либо вырезать второй/третий `<script>` с `THREE` **только если** понимаешь зависимости; безопаснее оставить.
7. Обнови `mechanicVisuals` в первом скрипте, если финальные визуалы ссылаются на названия кейсов.
8. Пройди QA.
9. Проверь в браузере: навигация, overview, notes, тёмные слайды.

## QA-чеклист

- [ ] Один `.active` на первом слайде.
- [ ] У каждого слайда `data-title`, chapter/counter, notes.
- [ ] Каждое семейство: ограничение → кейсы → паттерн.
- [ ] У кейсов есть source/tag и оговорка по цифрам.
- [ ] Есть блок рисков и возврат к карте заказчика.
- [ ] Финал — вопросы к способу работы, не список технологий.
- [ ] Нет переполненных слайдов: заголовок читается с проектора.
- [ ] Watermark и палитра Open Plus сохранены.

## Чего не делать

- Не собирай с нуля CSS и watermark.
- Не превращай доклад в каталог вендоров или product pitch.
- Не используй формат практикума (промпт-shell, copy-btn) — другой жанр.
- Не добавляй 3D «для красоты», если нет сцены и смысла.
- Не ставь в первый экран статистику, расписание и вторичные блоки.
